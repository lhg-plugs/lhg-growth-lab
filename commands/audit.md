# /lhg-growth-lab:audit —— 实验设计体检

用户输入在 `$ARGUMENTS` 中：`[实验方案目录或文件] [--fix]`。缺省扫描当前目录下的 markdown 实验方案。

## 流程

### 1. 跑脚本
```bash
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/audit/gl_audit.py --target <目录或文件> --format text
```
记下 blocker / warning 的数量与明细（含文件、行号、规则说明）。

### 2. 分级与修复
- blocker（缺假设/无对照组/提前停止风险）：逐条修。`--fix` 不自动改方案内容（设计要人定），只输出"待修清单"；修完复跑脚本确认消失。
- warning（样本量未估算/随机化未说明/多重比较未校正/周期过短/新奇效应未考虑）：补上或写豁免理由。
- 修不掉的 → 列入"需人工处理"，不许为清零改规则。

### 3. 人工评审（脚本覆盖不到的）
- 假设的"因为"部分是真因果还是套话？
- OEC 的口径定义够算吗（分子分母、统计周期）？
- 分流单元选得对吗（按用户还是按访问？登录态与非登录态混在一起吗）？
- 护栏指标有没有？实验期间有没有其他大动作污染？

### 4. 输出报告
按模板输出，存为 `docs/gl-audit-YYYYMMDD.md`：
```markdown
# 实验设计体检报告（日期）
## 结论：通过 / 不通过
## blocker（n）：已修 n，剩余 n
## warning（n）：已处理 n，豁免 n（理由）
## 人工评审结论
## 需人工处理
```

## 硬规则
- 有 blocker 就说"通过" → 不许。
- 为清零改脚本规则或阈值 → 作弊，不许。
- 审计的是"设计"：实验跑完后的显著性判定走 `/lhg-growth-lab:ab-significance`，不要混在一起。

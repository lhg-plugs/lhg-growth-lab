# lhg-gl-stats：统计判定

> 目标：让小白也能正确跑显著性检验、读懂结果——p 值只回答"是不是运气"，"值不值得做"要另算。
> 核心纪律：**样本未达标不谈 p 值；p≥0.05 就是没过，不过就是不过；显著 ≠ 值得做。**

## 1. 何时使用

- 实验跑完，要判定结果 → 跑全流程（先过资格检查）
- 拿到两组数据，想知道差异可不可信 → 用 `ab-significance` 命令
- 同时看了多个指标，不知道怎么算账 → 用 Bonferroni（第 5 节）
- **不适用**：样本量/周期未达标 → 回去补样本，不要"先算个 p 值看看"

## 2. 输入与输出

### 输入
- 两组数据：转化率类（转化数/样本量）或均值类（均值/标准差/样本量）
- 实验方案（确认口径、样本量目标、停止规则）

### 输出
- 资格检查结论（样本/周期/分流/口径四项）
- 脚本判定结果（p 值、置信区间）
- 最终结论三选一：采纳 / 放弃 / 继续跑（补样本）

## 3. 分步方法论

### 第 1 步：资格检查（跑脚本前，必做）
- [] **样本量**：两组都达到当初估算的 N 了吗？没达标 → 结论只有"继续跑"，不许谈 p 值
- [] **周期**：跑满了吗？提前停了 → 标"提前停止，结果可能虚高"，结论降级
- [] **分流**：比例符合设计吗？SRM 异常 → 先修分流，不谈显著性
- [] **口径**：和方案一致吗？换了口径 → 结论作废，重算

任一项不过，先处理再判定。**跳过资格检查直接算 p 值，是本 skill 第一大忌。**

### 第 2 步：选检验、跑脚本
| 数据类型 | 命令 |
|---|---|
| 转化率（转化数/样本量） | `ab_stats.py ztest --x1 <对照转化> --n1 <对照样本> --x2 <实验转化> --n2 <实验样本>` |
| 均值（如下单金额） | `ab_stats.py ttest --mean1 <均值> --sd1 <标准差> --n1 <样本> --mean2 …` |
| 多个指标同时判定 | `ab_stats.py bonferroni --p "<p1>,<p2>,<p3>"` |

脚本输出含 p 值、差值、95% 置信区间和一句话 verdict，直接用，不要自己手算。

### 第 3 步：读懂 p 值（给小白的人话版）
- p 值 = **"如果两组其实没差别，看到这么大（或更大）差异的概率"**
- p<0.05 → 这种差异不太可能是运气 → "显著"
- p≥0.05 → 当前数据不足以排除运气 → "不显著"，**不是"证明没差别"**，只是"证据不够"
- 0.05 是事先定的线：p=0.051 和 p=0.049 没有本质区别，但线就是线——**不许"边缘显著也算赢"**

### 第 4 步：看置信区间与业务价值
p 值只回答"是不是运气"，下面这个问题 p 值回答不了：
> "提升 0.3%，p<0.05，值得全量吗？"

看 95% 置信区间：
- 区间全在 0 以上 → 方向可信
- 区间很窄且贴近 0（如 +0.1%~+0.5%）→ 统计显著，但业务价值可能为负（开发/维护成本）
- 区间很宽（如 -2%~+8%）→ 数据还太噪，结论是"证据不足"不是"没效果"

**最终结论 = 统计结论 × 业务价值**，两个都要过。

### 第 5 步：多重比较（Bonferroni）
同时判定 m 个指标时，假阳性会膨胀（m=5 时，至少 1 个误报的概率约 23%）。处理二选一：
1. **只定 1 个 OEC 做判定**，其他只看不判（推荐）
2. 跑 `bonferroni --p "…"` 校正：校正后 p<0.05 的才算数

**不许**：5 个指标里挑最显著的报，其他的不提——这是 p-hacking。

### 第 6 步：下结论（三选一）
- **采纳**：p<0.05（校正后）且提升幅度有业务价值 → 全量/固化
- **放弃**：p≥0.05，或提升无业务价值 → 写清"学到了什么"归档
- **继续跑**：接近显著但样本未达标 → **补到 N 再判定**，不是"再看看数据"

结论句式："实验 X 判定为：p=0.0xx（<ztest|ttest> 双侧），提升 x%（95% CI [a,b]），因为……"

## 4. 反模式

- ❌ 样本不够先算 p 值"看看"——看了就会忍不住下结论
- ❌ p=0.06 说成"边缘显著"——线就是线
- ❌ 只报 p 值不报提升幅度——"显著"可能是 +0.1%
- ❌ 多个指标挑显著的报——Bonferroni 或全报，二选一
- ❌ "不显著 = 没效果"——不显著 = 证据不够，别把"没证据"当"证据没"
- ❌ 用单侧检验把 p 值减半——除非实验前就写明只关心一个方向，否则一律双侧

## 6. 常见问题

- **Q：p<0.05 但提升只有 0.2%，全量吗？** A：算一笔账：0.2% 带来的收入 vs 全量后的维护成本。统计显著只负责"是不是运气"，"值不值得"另算。
- **Q：对照组反而显著更高，算"显著"吗？** A：算统计显著，但结论是"放弃"——方向反了，改动有害。
- **Q：能不能用 AI 直接判断，不跑脚本？** A：不能。p 值是数学，不是语感；让 AI 心算等于编数字。脚本零依赖，跑一下 1 秒。
- **Q：样本量刚达标 p=0.04，要不要多跑几天"更显著"？** A：不要。停止规则说达标即判就判；多跑几天是可选停止（反模式 5），p 值会虚好看。
- **Q：两组样本量差很多（如 1000 vs 9000），能直接比吗？** A：先查 SRM——设计 50/50 跑出 10/90，多半是分流 bug。修好分流再谈显著，分流坏了 p 值无意义。

### 读报告示例
```
对照组：100/1000（10.0%）；实验组：130/1000（13.0%）
z = 2.10，p = 0.0355（双侧），差值 +3.0pp（95% CI [+0.2pp, +5.8pp]）
```
解读：p<0.05，差异不太可能是运气；提升 3 个百分点，置信区间全在 0 以上，方向可信。
结论：采纳（若 3pp 提升有业务价值）——记得先过资格检查四项。

### 资格检查不过的三种标准话术
- 样本不够："两组样本 X/X，未达目标 N，当前 p 值不可信。继续跑到 N 再判定。"
- 提前停止："实验提前 X 天停止，结果可能虚高。结论降级为探索性发现，建议重跑。"
- SRM 异常："两组比例 X:Y 偏离设计，分流疑似异常。先排查分流，暂停显著性讨论。"

> 一句话总结：显著性判定是"先验资格、再算数学、最后谈业务"的三段式——跳过任何一段，结论都不可信。

### 报告存档
判定报告存 `docs/gl-significance-YYYYMMDD.md`，与实验方案放一起。3 个月后回看：当初"采纳"的实验，业务指标真的涨了吗？这是校准团队判断力的最好材料。

## 7. 自检与反馈

判定前自问：
1. 资格检查四项过了吗？→ 没过不许谈 p 值。
2. 检验选对了吗（转化率 ztest / 均值 ttest）？→ 选错等于白算。
3. 结论是三选一之一吗？→ 模糊话打回。

标准冒烟用例：`ab_stats.py` 的数学正确性（z=2.1027/p=0.0355 手工验算值、t 分布数值积分对照、样本量缩放律），见仓库根 `smoke_test.py`。
